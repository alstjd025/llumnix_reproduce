## 3. 복원 뒤 검증

**저장소**: 두 저장소에서 `git fetch` 후 §0 의 sha 와 대조한다. 백업에는 저장소 사본이
없으므로 "앞선 쪽을 취한다" 같은 판단이 필요 없다.

**결과 데이터**: 백업 루트의 정답표로 양방향 대조한다.

**바이트까지 볼 때**는 정답표의 `tier1_bytes` 열과 복원된 run 을 비교한다.

    awk -F'\t' 'NR>1 {print $1"\t"$6}' "$B/backup_manifest_node_2026-09-23.tsv" > /tmp/want_bytes.tsv
    ssh "$N" "cd $SRC && for d in results/*/; do r=\$(basename \$d); \
      b=\$(find \$d -type f ! -name tbt_events.jsonl ! -path '*/agent_logs/*' -printf '%s\n' | awk '{s+=\$1} END{print s+0}'); \
      printf '%s\t%s\n' \$r \$b; done" > /tmp/have_bytes.tsv

2026-08-27 에 한 번 지워진 적이 있으므로 이 검사를 건너뛰지 않는다.

## 5. 이 전송에서 걸린 것 — 다음에 같은 일을 할 때

**exFAT 이라 `rsync -a` 를 쓰면 안 된다.** 권한·소유자를 보존할 수 없어 매번 실패한다.
`-rlt` 로 충분하고(`-a` 에서 `p g o D` 를 뺀 것), `--no-perms` 류는 따로 붙일 필요가 없다.

**`--modify-window=1` 이 없으면 두 번째 실행이 전부를 다시 보낸다.** exFAT 은 수정 시각을
2 초 단위로만 저장해서 rsync 가 매번 "다르다"고 판단한다.

**`while read` 루프 안의 `ssh` 에는 `-n` 이 필요하다.** 없으면 ssh 가 루프의 stdin(=run
목록)을 통째로 먹어서 **첫 run 하나만 처리하고 조용히 끝난다.** 실제로 그렇게 한 번 끝났다.

**ssh 는 ControlMaster 로 한 번만 연다.** known_hosts 에 쓸 수 없는 환경이라 연결마다
호스트 키를 물었고, 1,841 회 연결에서는 진행이 불가능했다. 마스터 연결 하나를 열어
`-o ControlPath=...` 로 재사용하면 그 질문이 한 번으로 끝나고 핸드셰이크 비용도 사라진다.

**`bash -c '...'` 에는 셸 변수가 넘어가지 않는다.** `$DEST` 가 빈 채로 `mkdir /agent_logs`
가 실행돼 읽기 전용 루트를 건드렸다. 현재 셸에서 그대로 돌리거나 `export` 한다.

**작은 파일 5,525 만 개는 파일 단위로 보내면 안 된다.** exFAT 은 파일마다 최소 한 클러스터를
차지하므로 용량으로도 불가능하고(128 KB 클러스터면 7 TB), 네트워크로도 왕복 횟수가 시간을
결정한다. run 마다 tar 로 묶어 1,841 개로 만들면 둘 다 사라지고, 아카이브 안의 이름은
맥의 대소문자 무시 파일시스템이 보지 않으므로 이름 충돌 위험도 같이 없어진다.

**받는 중에는 `.part` 로 쓰고 끝나야 이름을 바꾼다.** 중간에 끊긴 파일이 완성본으로 보이지
않고, 다시 실행하면 그 run 만 새로 받는다.
