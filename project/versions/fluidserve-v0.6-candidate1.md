# FluidServe v0.6-후보1 — 무엇인가, 무엇이 아닌가

**이름**: v0.6-후보1 (EXP-155의 "새 모델", arm `fsnewh25`·`fsnewh100`·`fsnewh200`). **채택하지 않았다.**
**날짜**: 2026-11-10
**바이너리**: 스케줄러 `5f6fa02a`(v0.5.5, `/home/nxclab/tools/staging/scheduler-forecast`, 바깥 `81aeace`) + 아래 플래그, 게이트웨이 `05745270`
**앞 버전**: v0.5

**목표(사용자와 합의, 2026-11-09)**: horizon을 클래스 배분 손잡이가 아니라 **예측 정확도를 통제하는 값**으로 만든다. h를 바꾸면 예측이 얼마나 멀리 보고 그래서 얼마나 불확실한지만
바뀌어야 하고, 어느 클래스를 얼마나 받는지는 바뀌지 않아야 한다.

## 1. v0.5에서 바뀐 것

| 무엇 | v0.5 | v0.6-후보1 | 플래그 |
|---|---|---|---|
| KV 투영 | h iteration 뒤 한 시점: 지금 KV + decode 수 × h − outflow(생존확률, z 1.65 하한) | 기간 중 **정점**: τ ∈ {0, h/4, h/2, 3h/4, h}에서 지금 KV + n·τ + 도착률 × τ × 지금 iteration 시간 − 기대 회수(τ), 여기에 z × 실측 오차(τ)를 더한 값의 최대 | `--fluidserve-peak-forecast` |
| 도착 추정 | 없음 | 이 인스턴스로 보낸 프롬프트의 지수 평균(반감기 10초) | `--fluidserve-arrival-halflife-ms 10000` |
| 여유 | outflow의 z 1.65 하한 | 과거 예측이 τ 뒤 실제 KV와 달랐던 정도의 지수 평균(이득 1/4) × z 1.65 (TCP RTTVAR 방식) | `--fluidserve-forecast-z 1.65` |
| 처리 중 요청 보호 | 넣은 뒤 평균 iteration 시간(이번 prefill을 h로 나눠 얹음) ≤ 허용 속도 × 0.9, ≤ 처리 중 요청들의 남은 토큰당 허용치 | 지속 부하(넣은 뒤 decode + 관측 prefill 비중 × 지금 iteration 시간) ≤ 허용 속도 × 0.9, 일회성 지연(큐의 prefill + 이번 프롬프트) ≤ 처리 중 요청들의 최소 ladder 여유 | `--fluidserve-slack-protect` |
| 새 요청 자신의 속도 판정 | 넣은 뒤 평균 iteration 시간 | 지속 부하 | 같음 |
| 메모리 판정의 속도 상한 KV(capKv) | 대기 prefill ÷ h 몫 포함 | 지속 부하 식에서 역산(h 없음) | 같음 |

그대로인 것: 미리 잡는 KV 청구 min(h, 기대 출력), 지연 보정, 판정선의 0.9 계수, 물리 KV 0.95, 클래스 선호·인스턴스 상한.

## 2. 측정 (EXP-155, 한 시간 trace, 2회씩, 같은 세션의 v0.5와 비교)

| | v0.5 (h100) | v0.6-후보1 h25 | h100 | h200 |
|---|---|---|---|---|
| 모든 도착 | 79.7 | 63.9 | 64.0 | 60.3 |
| 거절 % | 20.1 | 35.8 | 35.8 | 39.6 |
| admitted | 99.95 | 99.86 | 99.92 | 99.97 |
| preemption (run당) | 575~721 | 2~3 | 0 | 0~3 |

- 예측의 쏠림: 여유를 뺀 예측은 실제 정점 대비 +0.5 / 0.0 / −0.5 %(h25/100/200), 퍼짐만 2.1 → 5.8 → 8.4 %로 커진다(오프라인 재계산). **목표대로.**
- 클래스 배분: h25 = h100(아홉 지표·클래스별 거절 모두 차이 없음). **h200은 아직 deepresearch 쪽으로 움직인다**(chat −6.3, swe −5.0, deepresearch +5.0).
- **대가**: v0.5보다 모든 도착 −15.7. 받아들인 요청은 다 지키지만 지켜도 되는 요청까지 거절한다. 예측이 정확해지자 판정선(평균 iteration 시간 ≤ 예산 × 0.9, KV 0.95, z 1.65)이
  필요보다 엄격하다는 것이 드러났다 — v0.5는 반복 prefill 몫을 작게 잡는 오류가 이 엄격함을 상쇄하고 있었다.

## 3. 다음 후보(v0.6-후보2)로 갈 방향
