# EXP-137 — 클래스를 읽는 메커니즘 둘을 같이 끄면

실행 전에 씀. 2026-09-14 KST. **EXP-136(Qwen) 뒤에 Llama 로 되돌린 다음 돈다.**

## 1. 왜

**이 정책에서 요청의 클래스를 읽는 메커니즘은 둘뿐이다** — 클래스 선호와 클래스별 인스턴스
상한(class-pin 과 class-harm 은 모든 arm 에서 꺼져 있다). 그런데 **하나씩 빼면 점수가 반대
방향으로 움직인다.**

| 뺀 것 | 정적 35 req/s, 모든 도착 |
|---|---|
| 배포 설정 | 73.3~75.5 (n=4) |
| **선호만** | 69.9~71.4 (n=5) → 선호는 **+1.9~+5.6 점을 번다** |
| **상한만** | **85.6~85.8** (n=2) → 상한은 **10.3~12.5 점을 잃게 한다** |
| 선호+보유+상한 | 82.9~84.4 (n=2) |

**부호가 반대이므로 합을 표에서 읽을 수 없다.** 그리고 EXP-133 이 이미 보였듯 **다른 요소가
대신해 주고 있으면 하나씩 빼는 방식은 과소평가한다** — 보유가 단독 0 인데 누적에서 3~6 점
손해였다.

**"클래스 인식 배치 전체가 얼마인가"는 아직 측정되지 않았다.**

## 2. 둘이 왜 같은 메커니즘이 아닌가

둘 다 클래스를 읽지만 **하는 일이 다르다.**

| | **선호 (affinity)** | **상한 (cap)** |
|---|---|---|
| 무엇 | `sortCandidates` 의 **가중치** | 정렬 **전에 후보를 지우는 필터** |
| 언제 | 항상 | 수요에서 유도한 한도에 닿았고 **동시에 다른 클래스가 자기 몫보다 부족할 때만** |
| 용량에 | **못 깎는다** (순서만 바꾼다) | **깎는다** (목적지를 지운다) |

**하나는 용량을 깎을 수 없고 하나는 깎는다 — 측정된 부호가 갈리는 이유가 그것이다.**

## 3. 설정

`noaffnocapt75` = 배포 설정(`fsv3capgnofrct75`)에서 **`--fluidserve-enable-affinity=false`
와 `--fluidserve-class-instance-cap=false` 둘만** 바꾼 것.
`FS_CAP_WINDOW_MULT=3.0` 은 상한이 꺼지면 작동하지 않지만 기동 줄 기준으로도 **정확히 두
플래그만 다르도록** 명시로 고정한다. `FS_INCUMBENT_BALANCE=true` 도 박는데 이는 컴파일
기본값과 같고 **EXP-134 의 `nocapt75` 와 같은 형태**여서 두 arm 이 서로 일관된다.

정적 2,100 rpm(35 req/s), 8 분, t75, **2 반복**. 약 40 분.

⚠ **Llama 에서 돈다.** 비교 대상 넷이 전부 Llama-3.1-70B 2,100 rpm 이다. 체인이 Qwen 에서
되돌리고, **네 포트가 Llama 를 서빙하는 것을 직접 확인한 뒤에만** 건다(`ready` 는 아무것도
기다리지 않는다). **`FS_PROFILE_DIR` 을 설정하지 않는다** — 기본값이 Llama 표다.

## 4. 판정 규칙 (실행 전에 정한다)

\|Δ\| < 1.0 차이 없음 / 1.0~3.0 판정 안 함 / ≥ 3.0 실재. 주 지표는 모든 도착,
옆에 admitted·거절률·goodput. 채점 `FS_SWE_TBT_MS=75`.

### 4.1 사전 예측과 그것이 뜻하는 것

**둘러싼 값으로 보면 82~84 언저리를 예상한다** — 상한만 끈 85.7 에서 선호의 몫(2~4 점)을
뺀 자리다. 그러나 **그것은 두 요소가 독립이라는 가정이고, 이 실험이 묻는 것이 바로 그
가정이다.**

| 결과 | 읽는 법 |
|---|---|
| **82~84** | 두 요소가 **독립**이다. 선호의 몫이 상한의 유무와 무관하다 |
| **85.7 에 가깝다** (선호를 꺼도 안 내려간다) | **선호의 몫이 상한 때문에 생긴 것**이다 — 상한이 후보를 지워 놓으면 정렬이 할 일이 남지만, 상한이 없으면 정렬이 무의미해진다. 그러면 **"선호가 4 점을 번다"는 상한이 켜진 세계에서만 참**이다 |
| **80 아래** | 둘을 같이 빼면 각각의 합보다 더 잃는다 = **서로 보완한다.** 그러면 클래스 인식 배치는 하나씩 평가하면 안 된다 |

### 4.2 무엇을 같이 본다

- **클래스별 점수.** 상한은 한 시간 trace 에서 총점 0 인데 deepresearch 를 2.0~3.4 점
  벌어 준다(EXP-135). 정적에서 총점이 올라도 **dr 이 잃으면 그것이 상한의 값**이다.
- **거절률.** 상한만 끄면 22~23% → 11.9~12.1% 였다. 선호까지 끄면 어디로 가는가.
- **`N_eff`(클래스가 실질적으로 몇 인스턴스에 퍼지는가)와 chat 없는 인스턴스 수.** EXP-132 가
  선호를 끄면 2.1 → 1.8 대로만 준다고 쟀다. **상한까지 끄면 그 값이 얼마인가**가 "클래스 인식
  배치가 실제로 만든 분리"다.

## 5. ⚠ 이 실험이 답하지 않는 것

**정적 한 셀, 한 도착률이다.** 선호의 몫은 45 req/s 에서 9.1~11.4 로 두 배가 되고, 상한의
비용은 한 시간 trace 에서 0 이 된다. **여기서 나오는 합을 "클래스 인식 배치의 값"으로
일반화하면 안 된다** — 그 문장을 쓰려면 도착률 축과 한 시간 trace 가 둘 다 있어야 한다.
