# EXP-120 — 고친 첫토큰 예측 + 메모리 제동

2026-09-10, 반복 1, 6조건. 바이너리 `87f657bd`, 8 × Llama-3.1-8B TP=1, 게이트웨이 `-v 0`,
도착률 6000 / 9600 / 12600 rpm = 100 / 160 / 210 req/s.
arm `fsv3ftml`(수정 둘 + `FS_MEM_LEVEL=true`), `fsv3ftms85`(수정 둘 + `FS_MEM_SAFETY=0.85`).

## 1. 왜 걸었나

EXP-118이 첫토큰 예측 수정 둘만 켰을 때 무릎 위에서 admitted가 90.0 → 73.3으로 무너지는 것을
쟀다. 기전은 **과대예측이 그 함대에서 유일하게 작동하던 admission 제동이었다는 것**이다 —
`obs_kv / cap_mem`이 p50 1.027이고 표본의 57.2%에서 1.0을 넘는 상태에서, 예측이 커서 생기는
거절이 풀이 더 넘치는 것을 막고 있었다. 예측을 정확하게 만들자 제동이 풀렸다.

EXP-119는 첫토큰 마감을 feasibility에 넣어도 그 자리를 대신하지 못한다는 것을 보였다 —
**같은 예측을 읽기 때문**이다(수정 켠 상태에서 마감 있음 74.1, 없음 73.3).
그래서 **다른 양(KV)을 읽는 제동**을 시험한 것이 이 실험이다.

## 3. 판정 — 사전 규칙에 따라 기각

사전 규칙은 **"offered가 대조군보다 높고 admitted가 85 위로 회복"**이었다.
**offered 28.7 / 34.9(대조 70.2), admitted 43.8 / 50.3.** 둘 다 크게 미달이다.

⚠ **그리고 조임의 signature가 아니다.** 조이기만 했다면 거절은 늘고 admitted는 **올라야**
한다 — 마감 arm이 그렇게 움직인다(거절 27.6%, admitted 97.1). 여기서는 **거절이 늘면서
admitted도 같이 무너진다**(33.8% / 43.8). 조임의 세기로 설명되지 않는다.

⚠ **예측이 또 틀렸다**: 실효 문턱이 더 낮은 `fsv3ftms85`(≈0.90)가 `fsv3ftml`(≈0.95)보다
**나았다**(34.9 대 28.7). 더 조인 쪽이 낫다. 둘 다 무너진 영역이므로 그 차이를 크게 읽지는
않지만, **"얼마나 조였나"가 설명 변수가 아니라는 것은 분명하다.**

## 4. 오늘 유일하게 개선된 것 — 이미 있던 플래그

**`--fluidserve-deadline-feasible`을 원래(과대) 예측과 함께 쓰는 것**이 오늘 세션의 유일한
순이득이다:

| req/s | 대조 off / adm / goodput | **+마감** |
|---|---|---|
| 185 | 82.2 / 91.5 / 79,415 | **84.2 / 98.1 / 83,885** |
| 210 | 70.2 / 90.0 / 77,149 | **72.3 / 97.8 / 82,756** |
| 250 | 60.9 / 87.2 / 80,125 | 57.6 / 96.3 / 79,353 |

**185·210에서 offered +2.0/+2.1, goodput +5.6%/+7.3%.** 250에서는 offered −3.3이지만
admitted +9.1이다. **⚠ 반복 1회이므로 채택 전에 반복이 필요하다.**

## 5. 무엇이 확립됐나 — 오늘 세 번 같은 일이 일어났다

| 무엇을 더 정확하게 만들었나 | 결과 |
|---|---|
| KV 천장 인하 (2026-09-10 이전 세션) | 거절 +8점, offered −10 |
| 첫토큰 예측 (교정으로 편향 제거) | admitted 90.0 → 73.3 |
| KV 투영 (level test로 편향 제거) | offered 70.2 → 28.7 |

**세 번 다 추정기를 더 정확하게 만들었고 세 번 다 나빠졌다.**
**모든 추정기의 오차가 하중을 받고 있었다** — 첫토큰 과대예측은 admission 제동이었고,
KV 투영 낙관은 문턱 여유였다. **명시적 조절기가 없으므로 오차들이 조절기 노릇을 하고 있었다.**

**그리고 예측을 더 잘 하는 것으로는 닫히지 않는다**: `x̂(t+H)`는 현재 상태로 조건화되는데
실제 `x(t+H)`는 **이 컨트롤러가 그 사이에 얼마나 받아들이느냐**에 달려 있다.
**컨트롤러 자신의 미래 행동이 자기가 예측하려는 양의 입력**이고, 열린 루프 예측기는 그것을
"앞으로 아무것도 안 받아들인다"로 놓고 푼다. 항 하나를 더해 닫을 수 있는 구멍이 아니라
**고정점 문제**다.

→ **다음은 예측 개선이 아니라 되먹임이다.** 설계와 그 사전 검사는 EXP-121에 적는다.
