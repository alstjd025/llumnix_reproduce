# EXP-91 — 클래스 선호(affinity)는 믹스가 움직이는 한 시간 trace에서 이득인가 손해인가

**실행 전에 쓴다. 2026-08-22 새벽 KST. 결과를 본 뒤 §3~§4를 고치지 않는다.**

## 1. 왜

정적 sweep에서 클래스 선호의 부호가 **도착률에 따라 뒤집힌다**는 것이 측정돼 있다(EXP-73,
2반복): 25/35 req/s에서 켠 쪽이 +2.8/+3.8점, **45 req/s에서는 끈 쪽이 +7.1점.** 기제도
측정돼 있다 — 선호는 클래스를 모아 **함대의 속도 다양성을 보존**하지만(저부하에서 이득),
모인 클래스의 KV가 소수 인스턴스에 쌓여 **KV 한계에 먼저 닿는다**(메모리 탈락 사유 18.8%
대 3.4%; B1이 잰 메모리 사유의 등장 지점 35 req/s와 교차점이 일치한다).

**그러면 도착률과 믹스가 둘 다 움직이는 한 시간 trace에서는 어느 쪽이 이기는가.** 수정 후
워크로드로는 잰 적이 없다(EXP-56의 한 시간 ablation은 수정 이전이라 인용 금지).

## 2. 조건

| | |
|---|---|
| arm | `fspfx`(배포 설정, 선호 켬) 대 `fsnoaff`(선호만 끔 — `--fluidserve-enable-affinity=false`, **정렬의 classShare 항과 피해 추정의 클래스 항이 둘 다 꺼진다**) |
| ⚠ | `fsnoaff`에 **`FS_PREFIX=true`를 명시로 박았다** — 이 arm은 prefix 플래그가 생기기 전에 쓰였고 컴파일 기본값에 의존하고 있었다. 두 arm의 차이가 선호 하나가 되도록 |
| trace | `fullb` — 한 시간, 도착률 10.8~45.0 req/s, 믹스가 시간대별로 움직임(swe 입력 비중 14~57%) |
| 반복 | 2. **반복이 바깥 루프**(같은 반복 안에서 두 arm이 이웃 시간대에 돈다) |
| 드라이버 | `run_exp91_hour.sh` (`run_exp30_dynamic.sh`의 스냅샷 + 검증 실패 시 중단 수정) |
| 규모 | **4조건 × 약 72분 ≈ 5시간** |

**⚠ 대조군은 이 세션의 `fspfx`다.** EXP-71의 fspfx(offered 81.0)는 게이트웨이 `GOMAXPROCS`
수정 **이전**이고, 그 수정이 45 req/s 근처에서 달성률을 +3.2~3.7 움직였는데 trace의 정점이
정확히 그 구간이다. EXP-71 값은 부차 참조로만 쓴다.

## 3. 예측과 반증 조건

**예측**: **켠 쪽(fspfx)이 이긴다.** trace가 대부분의 시간을 교차점(35~45 req/s) 아래에서
보내므로, 정적에서 잰 저부하 이득이 고부하 손해를 넘을 것이다.

**판정 기준**: 헤드라인은 offered 달성률(이 저장소의 한 시간 표준 — admitted·거절률·goodput을
같이 낸다). EXP-71에서 fspfx의 한 시간 반복 폭이 1.5점이었으므로 **3점**을 문턱으로 한다.

| 결과 | 읽기 |
|---|---|
| fspfx가 3점 이상 위 | 예측 확인 — "선호의 저부하 이득이 동적 trace에서 지배적" |
| **fsnoaff가 3점 이상 위** | **예측 반증** — 교차점 위 구간(정점부)이 전체를 지배하거나, 믹스 이동이 선호의 이득을 없앤다는 것. **구간별로 갈라 어느 쪽인지 본다** |
| 3점 안 | 이 trace에서는 구별 불가 — 그것대로 보고 |

**같이 내기로 미리 정한 것 넷**: ⑴ 구간별 점수(전환 구간 포함) ⑵ 클래스별 ⑶ 클래스당 유효
인스턴스 수(`fsnoaff`는 네 대에 가깝게 섞여야 한다 — 정적에서 3.78이었다. **이것이 플래그가
먹었는지의 유효성 검사이기도 하다**) ⑷ **시간대별 메모리 탈락 사유 비중** — 기제대로라면
fspfx의 메모리 사유가 trace 정점부에 몰려 있어야 한다.

## 4. 유효성

- 기동 줄 `verified:` (드라이버가 실패 시 중단하는 스냅샷)
- 유효 인스턴스 수로 선호 꺼짐을 결과에서 재확인 (§3의 ⑶)
- ⚠ 결과 디렉토리 `exp91r*_fspfx_fullb*`가 EXP-71의 `exp71*_fspfx_fullb*`와 arm 부분이 같다 —
  **glob은 실험 번호로 가른다**

## 5. 결과 (2026-08-22 20:29 KST, 4/4조건)

### 5.1 헤드라인 — 3점 문턱 안: **이 trace에서는 구별되지 않는다**

| run | offered | admitted | 거절률 | goodput |
|---|---|---|---|---|
| `fspfx` r1 / r2 (선호 켬) | **84.1 / 82.5** | 97.0 / 96.5 | 13.3 / 14.6% | 11,254 / 11,004 |
| `fsnoaff` r1 / r2 (끔) | **82.4 / 82.8** | 94.9 / 95.5 | 13.1 / 13.2% | 11,013 / 11,032 |

평균 차이 **+0.7**(켬이 위), 반복 폭 1.6 / 0.4. **사전 예측("켠 쪽이 3점 이상 위")은 확인되지
않았고, 반증 조건(끈 쪽이 3점 이상 위)도 아니다.** 규칙의 세 번째 칸 — 구별 불가 — 로 보고한다.
**정적에서 잰 저부하 이득(+2.8/+3.8)과 고부하 손해(−7.1)가 이 trace의 시간 구성에서 거의
정확히 상쇄된다.**

### 5.2 유일하게 폭 밖인 것 — **선호가 swe에 약 3점을 물린다**

| 클래스별 offered | chat | deepresearch | **swe** |
|---|---|---|---|
| 켬 (r1/r2) | 88.5 / 87.0 | 76.9 / 74.2 | **58.3 / 56.7** |
| 끔 (r1/r2) | 86.3 / 87.1 | 75.5 / 73.8 | **60.9 / 60.2** |

chat +0.9, deepresearch +0.9로 켠 쪽이 반복 폭 안에서 약간 위인데, **swe만 끈 쪽이 −3.0으로
범위가 겹치지 않는다**(켬 56.7~58.3 대 끔 60.2~60.9). **선호의 저부하 이득은 chat·dr이 받고
그 비용은 swe가 낸다** — A6·A8·EXP-90에 이어 **"총계가 클래스 거래를 가린다"의 네 번째 사례.**

### 5.3 유효성 검사 통과 — 두 arm의 함대 상태가 실제로 완전히 다르다

`separation_measures.py` (요청→엔진 조인, 한 시간 규칙 적용):

| | 켬 | 끔 |
|---|---|---|
| chat 없는 (인스턴스, 시각) 비율 | **27.5~33.2%** (≈전용 비-chat 인스턴스 1.1~1.2대) | **0.1~1.0%** (완전 혼합) |
| 최다 보유 인스턴스 교체 빈도 | 7.9~15.8회/시간 | **44.5~53.4회/시간** |
| 이동/잡음 비 (lag8/lag1) | 3.3~3.4 (실제 이동) | 1.9 (거의 잡음) |

**플래그가 확실히 먹었고, 함대 배치가 극단적으로 다른 두 상태가 같은 총계를 낸다.**

### 5.4 기제 검사 — 정적의 교차 기제가 trace에서도 그대로 보인다

10분 창 여섯으로 갈라 탈락 사유 중 **메모리**의 비중(%):

| | 창1 | 창2 | 창3 | 창4 | 창5 | 창6(정점) |
|---|---|---|---|---|---|---|
| 켬 r1 / r2 | 19.9 / 19.0 | 18.7 / 17.1 | 0 / 0 | 9.7 / 8.2 | 9.1 / 6.9 | 0.7 / **19.4** |
| 끔 r1 / r2 | 0.1 / 0.7 | 0 / 0 | 0 / 0 | 0 / 0 | 0 / 0 | 0.4 / 9.9 |

**선호를 켜면 KV가 모여 메모리 탈락이 trace 전반에 나타나고(7~20%), 끄면 사실상 사라진다
(≈0%).** 정적 45 req/s에서 잰 것(18.8 대 3.4%)과 같은 방향이다. ⚠ 예측("정점부에 몰릴 것")과
달리 **초반 창(chat 비중이 높은 구간)에도 크다** — 모이는 클래스의 KV 압력은 도착률만이 아니라
구성의 함수다.

### 5.5 판정 요약과 논문 문장

- **"한 시간 trace에서 클래스 선호를 끄면 총계가 좋아지는가"의 답은 아니오 — 안 변한다**
  (+0.7, 문턱 3점). 정적의 부호 반전(45 req/s에서 −7.1)이 동적 총계로는 상쇄된다.
- **쓸 수 있는 문장**: "클래스 선호는 이 동적 trace에서 총계를 바꾸지 않으면서, 전용 비-chat
  인스턴스 1대를 만들고(끄면 완전 혼합), 메모리로 인한 탈락을 만들며(7~20% 대 ≈0%), 그
  비용을 swe가 낸다(−3.0점)."
- ⚠ **일반화 주의**: 이 trace의 시간 구성(대부분 교차점 아래)에 대한 결과다. 정점이 더 길거나
  더 높은 trace에서는 정적 45 req/s의 부호(끔이 +7.1)가 총계에 남을 것이다.
