# EXP-69 — prefix 인식의 대조군: 새 워크로드에서 그 이득이 얼마인가

**상태**: 완료 (2026-08-08 20:19 KST, 6조건).
**정본 그림**: `results/aggregate_analysis/exp69_control`.
**짝**: EXP-68의 `fspfx`·`llm-d` 12조건. 같은 세션 창, 같은 바이너리 `5a572dc2`.

## 1. 무엇을 물었나

EXP-68이 prefix 인식을 켠 FluidServe(`fspfx`)와 llm-d를 비교해 **offered 달성률에서
+34.7 / +34.5 / +27.3점**(35/45/55 req/s)을 냈는데, **대조군을 안 돌려서 그중 얼마가 prefix
인식 자체에서 온 것인지 몰랐다.** EXP-68의 판정 규칙 H3이 그 이유로 "답할 수 없다"였다.

EXP-67이 prefix 인식의 이득을 **+11.0 / +7.8 / +2.6점**(45/55/70 req/s)으로 쟀는데, 그것은
**수정 이전 워크로드**다 — 모든 프롬프트가 정확히 12번씩 나가서 엔진 prefix hit rate가
83~86%였다. 재생을 없앤 뒤 그 값이 22~39%다.

**어느 방향인지 재기 전에는 몰랐다.** 캐시에 든 것이 적으면 아낄 것도 적지만, 반대로
**실제로 계산되는 prefill의 절대량이 커졌으므로 같은 비율의 절약이 더 큰 엔진 시간**을
뜻한다. 실행 전에 두 힘을 다 적어 두었다(`workload-decision.md` §3).

`prefix=false`를 확인했다.**

3 rate(2100/2700/3300 rpm) × 2반복 = **6조건**, 2.6시간. 연쇄 `/home/nxclab/tools/exp69_control.sh`,

## 3. 결과 — prefix 인식이 10~13점을 번다

요청 단위 offered 달성률. 괄호는 두 반복의 폭:

|---|---|---|---|---|
| 35 | 64.2 (63.4~65.0) | **77.6** (76.9~78.4) | **+13.5** | 42.9 (35.2~50.6) |
| 45 | 49.3 (48.9~49.6) | **59.4** (59.4~59.5) | **+10.2** | 24.9 (24.2~25.7) |
| 55 | 38.0 (35.6~40.4) | **48.3** (47.4~49.1) | **+10.3** | 21.0 (18.1~23.8) |

**세 rate 전부에서 이득이 두 arm의 반복 폭보다 훨씬 크다**(대조 폭 0.8~4.9, 처리 폭
0.1~1.7). 나머지 지표도 같은 방향이다:

| req/s | goodput 대조 → prefix | 거절률 대조 → prefix | admitted 대조 → prefix |
|---|---|---|---|
| 35 | 11,417 → **13,147** (+15.2%) | 25.3% → **16.0%** (−9.2%p) | 86.5 → 92.8 |
| 45 | 11,418 → **13,003** (+13.9%) | 43.2% → **35.4%** (−7.8%p) | 87.9 → 92.9 |
| 55 | 10,834 → **13,184** (+21.7%) | 53.7% → **46.3%** (−7.4%p) | 83.6 → 91.2 |

### 3.1 우위의 분해 — prefix 인식은 부분이지 원인이 아니다

| req/s | llm-d 대비 전체 우위 | 그중 prefix 인식 | 그중 기본 정책 |
|---|---|---|---|
| 35 | +34.7 | +13.5 (39%) | **+21.2 (61%)** |
| 45 | +34.5 | +10.2 (30%) | **+24.3 (70%)** |
| 55 | +27.3 | +10.3 (38%) | **+17.0 (62%)** |

> **대조군 `fluidserve`가 prefix 인식 없이도 llm-d를 세 rate 전부에서 앞선다**
> (64.2 대 42.9, 49.3 대 24.9, 38.0 대 21.0). prefix 인식은 우위의 30~39%를 만들고
> 나머지는 기본 정책이 만든다.

**이것이 "우리가 llm-d를 이긴 것은 그쪽 기능 하나를 베껴 왔기 때문 아닌가"라는 반론을
닫는다** — prefix 재사용을 전혀 안 보는 판정만으로도 이긴다.

### 3.2 ⚠ 이득의 기제가 "캐시 있는 곳으로 보낸다"가 아니다

**엔진이 보고하는 prefix cache hit rate가 거의 안 움직인다.**

| req/s | | 엔진 prefix hit | prompt 토큰/초 | 생성 토큰/초 | preemption |
|---|---|---|---|---|---|
| 35 | 대조 | 31.6% | 36,409 | 13,123 | 0 |
| | prefix | **38.5%** | 40,470 | 14,281 | 4 |
| 45 | 대조 | 23.9% | 36,272 | 13,137 | 147 |
| | prefix | **22.3%** | 39,711 | 14,485 | 270 |
| 55 | 대조 | 24.8% | 36,981 | 13,197 | 168 |
| | prefix | **23.3%** | 40,324 | 14,956 | 300 |

45와 55에서 **prefix 인식을 켠 쪽이 오히려 hit rate가 1.5%p 낮다.** 그런데 거절률은
7.4~7.8%p 낮고 prompt·생성 토큰은 둘 다 약 10% 높다.

**그러므로 기제는 배치가 캐시 친화적으로 바뀐 것이 아니라, prefill 비용을 정확히 매기게
되어 판정이 받아들일 수 있는 인스턴스를 덜 거부하게 된 것이다.** 이전에는 프롬프트를
전액 청구했으므로(정확히는 함대 하나짜리 스칼라 `prefillFraction`을 곱했으므로) 그
인스턴스에 이미 캐시된 부분까지 물려 `meanAfter`를 과대예측했고, `overGate`·`overIncumbents`가
과하게 걸렸다.

**이것은 EXP-67의 설계 문서가 미리 적어 둔 것과 같다** — `sortCandidates`의 점수가
`w·share + (1−w)·room`이고 **prefix는 그 어느 항에도 안 들어간다.** feasibility 판정과 TTFT
판정에만 들어가므로 캐시가 있는 쪽과 없는 쪽이 둘 다 feasible이면 클래스 점유율이 이긴다.
**지역성은 feasibility가 구속력을 가질 때만 생기는데, 여기서는 그렇지 않았다.**

→ **논문에 쓸 때 "prefix-aware routing"이라고 쓰면 안 된다.** 쓸 수 있는 것은
**"prefill 비용을 인스턴스별로 정확히 매긴다"**이고, 그 정확도가 admission을 덜 보수적으로
만든다.

### 3.3 EXP-67의 H2는 이 워크로드에서 **잴 수 없다** — 실패가 아니다

EXP-67의 H2가 "task당 유효 엔진 수 2.08 → 1.6 이하"였고, 그때는 **12개 사본이 동시에
도착해서 흩을 수밖에 없었기 때문에** 답할 수 없다고 기록했다. 중복을 없앤 지금 다시 재
봤더니 **다른 이유로 답할 수 없다**: 55 req/s 조건에서 요청을 두 개 이상 낸 task가
**8~92개뿐**이다(전체 약 25,000 요청 중). 재생을 없앴으므로 task 하나가 요청 하나만 낸다.

> **이 지표는 이 워크로드에서 어느 방향으로도 측정되지 않는다.** 수정 전에는 사본이
> 동시에 와서, 수정 후에는 task가 한 번만 나와서다. 값을 인용하면 안 된다.

이것을 재려면 **한 task가 시간을 두고 여러 요청을 내는 워크로드**가 필요하다. 다중 턴
chat이나 multi-call agent job이 그 형태이고, 둘 다 이 저장소에 있으나 mixed 워크로드는
쓰지 않는다.

## 4. 실행 전에 적어 둔 판정 규칙에 대한 답

| # | 예상 | 결과 |
|---|---|---|
| A | prefix 인식의 이득이 **반복 폭보다 크게** 남는다 | **통과.** +13.5 / +10.2 / +10.3점, 폭 0.1~4.9 |
| B | 이득의 방향이 수정 전보다 **작아지는가 커지는가** — 미지 | **커졌다.** 45/55에서 +11.0/+7.8 → +10.2/+10.3. 45는 거의 같고 55는 1.3배 |
| C | 대조군이 llm-d를 이기는가 — 미지 | **이긴다.** 세 rate 전부 +21.2 / +24.3 / +17.0점 |

**B가 예상 밖이었고 그 이유가 3.2절이다.** 캐시에 든 것이 줄어도 이득이 안 준 것은,
이득이 캐시 재사용량에 비례하는 것이 아니라 **비용 추정의 오차**에 비례하기 때문이다.
재생이 사라져 실제로 계산되는 prefill이 커졌으므로 **전액 청구의 오차도 커졌고**, 그것을
고치는 값어치도 같이 커졌다.
