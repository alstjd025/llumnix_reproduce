# paper_experiment — 논문에 들어가는 결과마다, 그것을 만든 run을 고정한다

`paper_figures/`가 **그림**을 담고, `ms_dev/notes/numbers.tsv`가 **문서 사이의 수치 대조**를
담는다. 이 폴더는 그 둘 사이의 빈 칸을 채운다: **"이 결과는 정확히 어느 run들로 만들어졌는가."**

## 왜 glob이 아니라 명세인가

이 저장소가 run 선택에서 틀린 경우가 전부 같은 모양이었다. **glob은 그대로인데 그 밑의
디렉토리가 바뀌었다.**

| 언제 | 무슨 일 |
|---|---|
| EXP-57 (2026-08-05) | PolyServe를 프로파일 수정 후 다시 쟀는데 **옛 EXP-53 run이 같은 glob에 계속 걸려서**, 45 req/s에서 27.5와 35.6이 31.6으로 평균될 뻔했다 — 돌지 않은 정책을 그리는 것이다 |
| EXP-68 (2026-08-08) | 새 arm `fspfx`가 세 그림 스크립트의 arm 표에 없어서 **조용히 빠졌고**, 남은 arm으로 그럴듯한 그림과 범례가 나왔다 |
| EXP-80 (2026-08-13) | 수정 후 run을 `>= 260808`로 셌는데, 워크로드 수정은 **KST 08-08 11:00**이고 디렉토리는 러너 파드의 **UTC−7**로 찍혀 16시간 뒤진다. 경계는 `260807_1900`이고, 그 컷이 **유효한 llm-d 조건 여섯 개를 버렸다.** 계획이 손으로 대조하기 전까지 틀린 채였다 |

**glob은 미래에 대한 약속이고, 명세는 과거에 대한 기록이다.** `verify.py`가 명세를 다시
해결해 보고 집합이 달라지면 **실패한다** — 조용한 변화를 시끄러운 변화로 바꾸는 유일한 방법이다.

## 무엇을 복사하고 무엇을 안 하는가

run 하나가 657 MB인데 그 안에서 **`metrics.csv`는 4.8 MB**이고 **`tbt_events.jsonl`이 568 MB**다.
후자를 읽는 것은 ITL CDF 그림 둘뿐이고, 토큰당 시간은 지금 `metrics.csv`에서 유도한다
(`implementation.md` §32에서 클라이언트가 기록한 값이 실제의 1/1.92였던 것을 고친 뒤로).

→ **채점의 입력만 보관한다.** 55개 run 짜리 sweep이 **0.4 GB**이고, 통째로 복사하면 36 GB다.
→ 이게 실질적으로 필요한 이유: **`results/`는 1.5 TB까지 차서 잘라낸 적이 있다.** 논문 결과가
   디스크 압박 한 번에 사라질 디렉토리에 매달려 있으면 안 된다.

## 무엇을 기록하는가 — 전부 이미 있는 파일에서 읽는다

**손으로 옮겨 적는 것이 없다.** 한 수치가 두 곳에 복사되고 한 곳만 갱신되는 것이 이 저장소가
가장 자주 겪은 오류이고, 2026-08-06 하루에 같은 모양을 네 번 고쳤다.

| 어디서 | 무엇이 |
|---|---|
| `results/<run>/run_config.json` | 모델, 도착률, 지속 시간, 시드, 엔진, **워크로드 설정 전체**(SLO 블록과 클래스 믹스 포함) |
| `results/exp07_meta/scheduler_deploy_<세션>.yaml` | 배포된 스케줄러 spec = **그때 실제로 걸려 있던 정책 플래그 전부** |
| 디렉토리 이름 | 실험 번호, 세션, arm, mix, 도착률, **시작 시각(KST로 변환해서 적는다)** |

## 쓰는 법

```bash
# 고정한다
python3 paper_experiment/build_manifest.py static_sweep_2026-08 \
    --arm "FluidServe=results/*exp68s*_fspfx_m1_rpm_*,results/*exp80r2_fspfx_m1_rpm_*" \
    --arm "llm-d=results/*exp70*_llmdslo_m1f_rpm_*"

# 확인한다 — 그림을 다시 그리기 전에
python3 paper_experiment/verify.py static_sweep_2026-08 \
    --glob "results/*exp80r2_fspfx_m1_rpm_*"
```

`verify.py`는 세 가지를 **따로** 검사하고 실패 메시지가 어느 것인지 말한다.

1. **run 집합** — 목록의 run이 없어졌는가. 그리고 `--glob`을 주면, **그 glob에 새로 걸리는데
   명세에 없는 run**이 있는가(그림과 명세가 서로 다른 측정을 가리키기 시작한 상태다).
2. **입력** — `metrics.csv`가 바뀌었는가(해시). 다시 채점하는 것은 정상이지만 **파일이 바뀌는
   것은 정상이 아니다** — 부분적으로 다시 쓰였거나 shard가 다시 병합된 경우를 잡는다.
3. **수치** — 채점이 바뀌었는가. `load_run`은 두 번 고쳐졌고(§32의 토큰당 시간, 2026-07-28의
   거절 분모) **그때마다 기록된 모든 그림이 조용히 다른 양이 됐다.** 여기서는 표를 다시
   계산해 차이를 낸다.
