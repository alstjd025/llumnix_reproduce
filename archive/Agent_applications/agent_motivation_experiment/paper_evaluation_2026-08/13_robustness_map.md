# 로버스트니스 반문 → 증거 대응표

**2026-08-21.** 반문 원문(사용자 정리): *"llm-d나 다른 것들 대비 tail latency를 너무 크게
희생하고 gain을 얻는 것 아니냐 + robustness under workload distribution shifts and
prediction error."* 앞 절은 [12_tail_objection.md](12_tail_objection.md)가 닫는다.
뒤 절을 형태별로 가른다 — **"shift"와 "error"가 실제로는 네 가지 다른 것**이고, 각각 증거가
다르다.

| 반문의 형태 | 무엇이 흔들리나 | 증거 | 상태 |
|---|---|---|---|
| **믹스가 움직인다** (chat↔agent 비율) | 클래스 구성 | **EXP-71 한 시간 trace** — Azure 실측에서 유도한 스케줄로 믹스가 시간대별로 움직인다(swe 입력 토큰 비중 14~57% = 4.07배; Azure 원본은 4.71배). 결과: offered 81.0 대 llm-d 56.7 (2반복, 폭 1.5/1.8). **구간 전환에서**: s1(chat 93%)→s2(swe 22%)에서 도착률은 7%만 오르는데 llm-d는 45점 잃고 우리는 99.2→79.6 | ✅ 있음 |
| **길이 분포가 움직인다** (프로파일이 낡는다) | `classes[]` — **런타임에 안 고쳐지는 유일한 입력** | **EXP-90 `stale` arm** — 실제 배포됐던 3.4배 드리프트 | ✅ **총계 무변화, 클래스 거래** — 틀린 클래스(dr)가 −7.5점, 나머지가 +5 안팎. 기제 확인됨(메모리 사유 19% → 0.1%) |
| **prediction error: 데이터 부족** | 프로파일의 표본 크기 | **EXP-90 `n25/n250/n1000`** | ✅ **12초짜리도 잡음 밖 손실 없음.** 오프라인 오차 곡선(B6)이 결과로 이어지지 않는다 — 결과는 분포 꼬리 모양에 둔감하다 |
| **prediction error: 모델 자체** | step 시간·KV 투영 | **[B5](09_accuracy.md)** — 셋 다 실측 정확(step p50 비 0.95~1.00, KV 3.5~5.7%). **상한**: EXP-64가 정답 길이를 줘도 −0.2점. ⚠ **오차 주입은 성립 안 함** — `noteResidual`이 학습해 되돌린다 | ✅ 있음 |

**논문에 쓰는 문장의 형태**: "우리는 X에 robust하다"가 아니라 **"이 설계에서 오차가 남을 수
있는 곳은 런타임에 갱신되지 않는 길이 분포 하나뿐이고(나머지는 보정 루프가 있다), 그것이
⑴ 트래픽 N분이면 충분해지고 ⑵ 실제로 겪은 3.4배 드리프트에서 Y점을 잃는다"**로 쓴다.
EXP-90이 정했다: **⑴ 12초면 충분하다(총계 기준) ⑵ 실제 3.4배 드리프트도 총계는 안 움직이나
틀린 클래스가 −7.5점을 내고 나머지가 나눠 받는다.** 정본 `EXP-90_profile-robustness.md` §5.

⚠ **빠져 있는 형태 하나 — burst.** 도착률이 갑자기 뛰는 것(제안에 있던 "갑자기 긴 generation이
몰리는 burst"). 한 시간 trace가 도착률 변화(10.8~45.0 req/s)를 담지만 **급격한 계단**은 아니다.
필요해지면 trace에 계단을 넣은 변형 하나로 닫을 수 있다. 지금 계획에는 없다.
